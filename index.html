Introduction

This is not another checklist app — it’s an AI automation control room. Same language as the welcome screen, then the path from first launch to a live agent.

What is Testquo?

An AI agent that lives inside your test suite — and works the way elite QA teams expect

Testquo is your on-desk AI partner for quality engineering. It wires tools, enforces team rules, and drives Playwright or Selenium automation through Cursor — without mixing client projects. You stay pilot-in-command; the agent handles the heavy lift.

One folder per window. Think mission control, not a multi-repo IDE. From a bound suite you plan, generate, verify, and report (tickets, regression packs, Testpad, multi-test reports) while each client stays in its own secure bind.

1

Awaken the agent

Open a recent project, or hit Bind New Agent → and walk Project source → Connections → Agent rules → Bind project. Your AI is suite-locked in minutes.

2

Power the stack

Cursor fuels the intelligence. Plug in GitHub, Jira, Testpad, and more only when a workflow needs them. Agent rules keep every AI session on-brand for your QA standards.

3

You fly the gates

Approve Testplan → Automate Now → Verify Automation Script → Execute Run. The agent commits locally; you push and open the SIT PR from Workspace → Git — human authority, AI velocity.

After install — activate your AI access

Before the agent can bind a suite, Testquo verifies you. Complete these steps once — after that, you walk straight into the control room.

  1. Open User access
    Launch Testquo. On the welcome screen, the status chip next to Agent ready is your access pulse (Sign in required, Registration required, Pending approval, or Access approved).
    1. Click that chip to open the User access dialog.
    2. Or click Bind New Agent → / a recent project — the same dialog opens if you are not cleared yet.
  2. Sign in with GitHub (when the dialog says Sign in to continue)
    Link your identity with one secure browser handshake:
    1. In Testquo, click Continue with GitHub.
    2. Your browser opens GitHub’s device login page (github.com/login/device). Keep Testquo open — it waits for the handshake.
    3. Copy the one-time code shown in Testquo (or type it into GitHub’s boxes).
    4. On GitHub, authorize Testquo, then return to the app — the dialog advances the moment sign-in succeeds.
    New to GitHub? Create an account at github.com/signup, then come back and click Continue with GitHub to unlock the agent.
  3. Fallback — create a personal access token (if Sign in to continue / browser login fails)
    When browser login fails, hangs, or the app says it is not configured, authenticate with a token instead:
    1. Open github.com/settings/tokens (sign in to GitHub in the browser if asked).
    2. Click Generate new token → prefer Generate new token (classic). Or go straight to github.com/settings/tokens/new.
    3. Give the token a note (for example Testquo desktop) and an expiry you are comfortable with.
    4. Under scopes, enable at least repo (required by Testquo). Generate the token and copy it once — GitHub will not show it again.
    5. Back in the Testquo User access dialog, click Or paste a personal access token.
    6. Paste the token (ghp_… or github_pat_…) and click Save token — your identity is now wired in.
    Official GitHub help: Creating a personal access token. The token is encrypted on this computer only (Electron safeStorage) — never shared to other machines.
  4. Register this GitHub account
    After GitHub sign-in (browser or token), the dialog title becomes Register for access — one tap to join the AI roster:
    1. Confirm the signed-in GitHub identity shown in the dialog.
    2. Click Register this GitHub account (one-time activation).
    3. Status becomes Pending approval until an admin sets your Users-sheet row to approved.
    4. When your admin confirms, open the dialog again (or stay on it) and click Refresh status. You do not need to register again.
    5. When the welcome chip reads Access approved, you are cleared — enter the dashboard below.
  5. Enter the AI dashboard
    Only after Access approved. This is Studio mission control: Workspace, Tickets & groups, Regression, Testplans, Reports, Project, and Settings — your agent’s home base.
    1. Resume a recent suite: on welcome, under Continue where you left off, open that project → Testquo rebinds this window and opens the dashboard instantly.
    2. First deployment: complete Bind New Agent (steps below) → on the Ready screen click Open project hub → you land on the Studio dashboard for that folder.
  6. Deploy Bind New Agent
    On welcome, click Bind New Agent → (or Get started → when you have no recents). The left rail is four precise stages: Project source → Connections → Agent rules → Bind project. (Suite Integration add-ons are coming soon — skip Project → Integration for now.) You must be approved before this continues — otherwise User access opens first.
  7. Project source — choose the suite the agent will inhabit
    Pick one path with the labels on screen:
    • Create a new project — scaffold an AI-ready Playwright or Selenium + Cucumber suite into a parent folder you choose.
    • Use an existing project → Clone from GitHub (sign in if needed, pick repo and clone base branch; Testquo prefers sit → uat → main/master, then creates your per-user qa/<username> branch from that base) or Attach a local folder already on this machine.
  8. Connections — power only what you need
    Connect tools now, or skip and wire them later in Settings → Configurations and Connections. For AI work you need Cursor (sign-in or API key) — that is the brain. Add Jira, Testpad, Google, Jenkins, and others when the workflow starts.
  9. Agent rules — teach the AI your QA standards
    Enable the General and Project Specific rules you want so every Cursor session follows your naming, locators, coverage, and safety bar. Tune these anytime in Settings.
  10. Bind project — lock the agent to the suite
    Review the summary, then confirm. Testquo writes the bind under .testquo/, syncs rules into AGENTS.md / .cursor/rules as applicable, and opens the main screen for that folder.
  11. First moves on the main screen
    Connect Cursor if you skipped it; open Tickets (after Jira + Save filter) or Studio for Suite pulse / Chat with AI; use Workspace → Git → Use my branch if you need qa/<username> on an attached local repo. Push and Push & open SIT PR only after you have local commits to share — day one is about activating the agent, not shipping the PR.
Mission rule: one window = one suite = one AI bind. Opening a recent project or finishing Bind New Agent locks this window to that folder. To switch clients later, use Bind a different project on the main bar (not Open Project, which only opens the folder in an editor).

Update the app

Keep your AI control room on the latest build. Packaged installs update themselves — no new .exe / .dmg hunt every release. Check, download, restart, done.

How it works: Testquo reads the same GitHub release feed used for Quick start downloads (outliant/ai-agent-testquo releases). When a newer version is published, the installed app can fetch it in the background and ask you to restart.

Update from Settings (recommended)

  1. Open App updates
    In a bound project (or from the hub), click the gear → left nav App updates. You can also jump from the in-app update strip → Details while a download is in progress.
  2. Confirm this install
    Read This install — for example Version 0.0.1. That is the build running on this machine right now.
  3. Check for updates
    Click Check for updates. Status messages you may see:
    • This install is up to date — you already have the latest published build.
    • Version X is available — download starts automatically.
    • Downloading… with a percent bar — wait until it finishes (keep Testquo open).
    • Version X is ready — click Restart and install.
  4. Restart and install
    When the update is ready, click Restart and install. Testquo quits, applies the new build, and relaunches — your projects, binds, and connections stay on this machine.
  5. Verify
    After relaunch, open Settings → App updates again and confirm This install shows the new version.

Update from the hub banner

On packaged installs, Testquo may check for updates when you open the app. If a download is running or ready, a strip appears across the top of the main screen:

  1. If you see Downloading version…, wait — or click Details to open Settings → App updates and watch progress.
  2. When it says Version X is downloaded. Restart to install., click Restart now.
  3. After relaunch, you are on the new build — resume your suite as usual.

Manual reinstall (fallback)

Use this only if auto-update cannot reach the feed, or an admin asks you to install a specific package:

  1. Download the matching installer from GitHub releases (same files as Quick start).
  2. Windows: run the new Testquo-Setup-*.exe over your current install.
  3. macOS: open the new DMG, drag Testquo into Applications (replace when asked). If Gatekeeper blocks an unsigned build again, clear quarantine once more: 
    sudo xattr -cr "/Applications/Testquo.app"
  4. Open Testquo and confirm the version under Settings → App updates.

Suite pulse — how to read it

Suite pulse summarizes formal / report leaves for this bound suite. It is split into two lanes:

  • Tickets — “Automation runs from Jira tickets.”
  • Regression — “Feature / full suite Jenkins & local runs.”

On each lane card you typically see:

  • Pass rate donut (overall for the pulse window)
  • Counts such as Passed / Failed / Flaky / Skipped (what appears depends on the data)
  • By environment bars (for example SIT / UAT / PROD)
  • Pass rate by run trend — click a bar to open that report in Reports
  • Open or Go to tickets / Go to regression to jump to that Hub tab

At the top of Suite pulse: All reports opens Reports. If something is still writing reports, N live also jumps to Reports.

Empty pulse? You need at least one formal Execute / Execute Regression (or Reports Rerun) that produced a multi-test-report leaf. Verify smoke alone may not fill the same picture as Execute.

Latest signal

Shows the newest report card for tickets and for regression. Click to open that report. If a lane has never run, the empty card points you to Tickets or Regression to get started.

In progress

While ticket coverage, script creation, executes, reruns, or fixes are running, they appear here. Click a card to open live progress. When idle you see: “Nothing running right now” and a hint that those workflows show up while they run.

Tickets is where you drive client-change automation from Jira. Use Backlog for one ticket at a time, and Groups when several tickets should share one Testpad plan and one run path.

When to use Tickets

  • Groups — related tickets that should share one multi-ticket plan and one Execute Run.
  • Resume a live run with View progress after you Hide the modal.

Lifecycle cheat sheet

Quick lookup for qa_automation_* Jira labels, the Tickets Action button they usually unlock, where scripts land, and the happy path from bind → PR. Use this when a row looks stuck or a label does not match what you expect.

Three independent states. Do not mix them up: (1) Jira Status (To Do / In Progress / Done) · (2) QA automation labels (this table) · (3) Git / execution (branch, PR, Testpad run result). Testquo drives labels; you drive Git from Workspace and Execute Run when ready.

Happy path (solo ticket)

required → in_progress → testplan_* → approved → script_need_to_test → ready_to_execute → done

Side paths: qa_automation_blocked (Resolve Blocker), qa_automation_fix (Fix Automation), qa_automation_testplan_only (plan only — stop after Approve).

qa_automation_in_progress Active analysis / discovery / implementation in flight Continue or View progress
qa_automation_blocked Cannot safely continue (real blocker — missing data, env, infra, untestable scope) Resolve Blocker

  • Groups share one Testpad plan and one Execute path; group status lives on the Data Resources → Ticket Groups sheet (not as a single Jira label on every member).

Tips & FAQ

Short answers to the questions people hit most often. For full steps, jump to the matching Hub section in the left nav.

Getting started

Do I need every connection on day one?

No. Bind a project folder and connect Cursor. Add Jira, Testpad, Google Sheets, and Jenkins when that workflow actually starts. Optional tools (Guru, Figma, Slack, BrowserStack, Decodo) can wait.

Open Project vs Bind a different project?

Open Project opens the already-bound folder in an external editor/app. Bind a different project points this Testquo window at another suite (usage charts and rules follow that bind).

Where does project config live?

Under .testquo/ in the bound folder (config.json, synced knowledge/, machine-local local/). Put secrets in .env.<name> / your secret manager — do not commit tokens.

Studio, agent, and rules

Where is Run agent?

Day-to-day work uses Tickets / Regression / Testplans primary buttons (they open the automation modal). The Studio top tab is Suite pulse + Chat with AI — it does not have Run agent. The Agent studio dock (task picker + Run agent) opens from some flows (for example after Testplans generate).

General vs Project Specific Agent Rules?

General Agent Rules are the integrity standard for this bound project (turning one off is the only way to stop that behavior). Project Specific adds constraints that exist only here — they do not replace General rules. Sync writes AGENTS.md and .cursor/rules. Use Update and sync after changes.

Tickets, Verify, Execute, Reports

Why is View Report missing after Verify?

Verify Automation Script is local smoke only (no Testpad write, no Jenkins). View Report appears after a formal Execute Run (or a Reports Rerun) that produces a report leaf.

Why can’t I pick Jenkins for Execute?

Connect Jenkins under Settings → Configurations and Connections, then retry Execute. Until then, use This machine.

Ticket is In group — can I still run it solo?

Often yes. The badge means membership on the Ticket Groups sheet. If the ticket still owns its own qa_automation_* lifecycle, Backlog actions remain available. Shared group Execute uses the Groups tab.

Approve did nothing / plan looks stale?

Edit the plan in Testpad first if needed. Approve Testplan re-reads the latest plan (including your edits) before labeling qa_automation_testplan_approved. Then use Automate Now.

Rerun vs Fix on Reports?

Rerun re-executes selected cases for a fresh result tab. Fix is for confirmed automation bugs (agent changes code). Website/product bugs stay failing — do not “fix” them away.

Git and environments

Agent pushed my branch / opened a PR?

It should not. Agents commit locally on qa/<username> only. You Push, Rebase onto sit, and Push & open SIT PR from Workspace → Git.

Why can’t I push to sit / uat / main?

Those branches are protected. Use your per-user branch, then open a PR into sit (and follow your promotion workflow for UAT/PROD). Never force-push or bypass protection.

Environment missing from Execute Run?

Settings → Project Environment: enable Include in Execute Run and click Save environments. Excluded profiles stay on disk but are hidden from pickers. PROD often uses Require confirmation.

Usage, updates, Integration

How do I clear API usage for a clean chart?

Settings → API usage → Clear log (after confirm). Clears only the currently bound project. Do not delete AppData usage files by hand.

Check for updates does nothing in npm run dev?

Auto-update runs in the installed app (packaged .exe / .dmg), not in npm run dev. On a real install: Settings → App updates → Check for updates, then Restart and install when ready. Step-by-step guide: Update the app.

Should I use Project → Integration?

Not yet — coming soon. Suite add-ons are not fully implemented. Use Configurations and Connections and Data Resources instead.
